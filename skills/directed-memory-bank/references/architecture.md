# 架构与设计取舍

## 1. 先说"要达成什么结果"

不是"让模型记住更多上下文"，而是：

> **让 Agent 在跨会话、跨工具、跨机器的条件下，对同一件事保持一致的判断；每个判断都可追溯、可推翻、不越权。**

把它拆成四个可验证的子目标，架构就是被这四个目标倒推出来的：

| 子目标 | 反推出来的设计 |
| --- | --- |
| 判断要可追溯 | L0 保存原文，L1 起每条记忆都带来源与置信度 |
| 判断要可推翻 | 纠错区优先于画像，冲突保留旧值 |
| 判断不能越权 | 写入门控 + 候选隔离区 |
| 换地方不能失忆 | 纯 Markdown/JSONL 为源，索引可重建，胶水层可重写 |

## 2. 分层：按**可信度**分层，不按时间分层

大多数"记忆"实现按时间切（近期 / 长期）。本项目按**证据强度**切：

| 层 | 内容 | 写入权限 | 保留 |
| --- | --- | --- | --- |
| L0-raw | 完整会话原文，逐份存档 | 只追加 | 永久，只作证据 |
| L0-portable | 脱敏后的 JSONL，跨工具迁移优先用这一层 | 只追加 | 永久 |
| L0-manifest | 来源定位清单：原始路径、归档范围、两层归档路径 | 只追加 | 永久 |
| L1-facts | 原子事实：完成动作、规则变化、遗留问题 | 已验证可直写 | 长期 |
| L2-scenarios | 每日会话流水 | 每轮追加 | 长期可衰减 |
| L2-projects | 进行中任务状态、决策、阻塞 | 原地更新 | 任务结束后清理行动项 |
| L2-skills | 可复用方法与流程 | 提炼后追加 | 长期 |
| L3-profile | 稳定背景、长期偏好、固定规则 | 需明确确认 | 长期 |

为什么这样切：**可信度决定它能不能影响行为**。时间分层只能回答"新旧"，回答不了"这是用户说的还是模型猜的"，而后者才是长期记忆翻车的主因。

## 3. 状态机

每条记忆都有状态，状态决定加载行为：

| 状态 | 含义 | 是否注入上下文 | 升级条件 |
| --- | --- | --- | --- |
| `confirmed` | 用户明确确认，或已被验证的事实 | 是 | — |
| `probable` | 多次独立观察一致 | 是（低权重） | 明确确认 |
| `observed` | 单次观察或模型推断 | 否 | 再次出现一致证据 |
| `rejected` | 用户否定过 | 否（但保留，防止重犯） | 用户改口并确认 |
| `expired` | 过期但仍保留 | 否 | — |

## 4. 写入门控：四步，不允许跳步

```text
提取 → 去重/冲突检测 → 状态判定 → 写入或候选化
```

判定规则：

- **直写 L1**：已验证的项目事实、已完成的动作、明确的规则变化；必须带来源证据。
- **进候选区**：用户可能的偏好、性格或能力推断、单次情绪、临时计划、未确认的长期目标。至少两次一致证据，或用户明确说"以后记住/一直这样"，才可升级。
- **进纠错区**：用户明确纠正，或新旧事实冲突。记录旧值、新值、证据、影响范围。
- **进复核区**：时间敏感、低置信度、长期未验证。复核前不当作当前事实。

## 5. 读取：优先级固定 + 混合检索

加载顺序（与"相似度最高"无关，与"可信度和当前性"有关）：

```text
规则 / 纠错  >  当前项目状态  >  已确认画像  >  相关 L1/L2  >  少量候选
```

`rejected` 与 `expired` 不主动加载。

批量召回交给本地混合检索（`scripts/memory_search.py`）：

- 只索引正式记忆层与可选的笔记库；**L0 原始会话默认不参与**，避免重复内容和 Token 膨胀。
- 中文向量模型 + 自实现 BM25（CJK 用字符二元组，不依赖分词库）+ RRF 融合，取 Top K。
- 分块按 Markdown 标题切，单块上限 600 字符；超长文件跳过并记日志。
- 索引是缓存：删掉、重建都不影响记忆本体。

## 6. 可移植性

纯 Markdown/JSONL 是唯一真相；SQLite 与向量索引都是可重建的派生物。换宿主时只有一层是脏的：

**"读会话日志 + 定时触发"的胶水层。** 这一层与平台绑定（日志路径、格式、调度器各不相同），必须在新宿主重写；其它全部可以整体拷贝。

## 7. 代价与边界

- **Token 成本**：靠分层 + 按需加载 + 不索引 L0 控制；代价是首次检索精度不如"全量灌入"。
- **维护成本**：每天要跑一次提炼。机器可做，但纠错和复核需要人确认。
- **单用户假设**：多用户下的隐私分区和权限没设计。
- **缺少量化指标**：目前只有行为断言（见 `migration.md` 的验证清单）。

## 8. 反面清单：这些做法一定失败

1. 让模型自由改写长期画像 —— 一次情绪会被固化成永久性格。
2. 用"最近 N 天"代替可信度分层 —— 旧但已确认的事实会被误丢，新但没确认的推断会被误用。
3. 把纠错实现成覆盖 —— 冲突消失，无法回溯，模型会在同一处反复犯错。
4. 把原始会话塞进日常检索 —— 上下文被重复内容占满，成本上升、判断变差。
5. 只存结论不存来源 —— 结论无法被审计，也就无法被安全推翻。
6. 用工具私有格式存记忆 —— 换工具即失忆，这正是本项目要解决的问题。
