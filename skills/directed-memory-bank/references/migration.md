# 迁移与验证

触发：用户说"迁移 / 换工具 / 换电脑 / 移植记忆"时执行。

## 1. 边界：什么是可移植的

| 可移植（整体拷贝） | 不移植（在新环境重建） |
| --- | --- |
| 记忆库本体：`AGENTS.md`、`L0-portable/`、`L0-manifest/`、`L1-facts/`、`L2-*/`、`L3-profile/`、`controlled-memory/` | `L0-raw/`（体积大、格式与平台绑定，按需单独迁移） |
| `scripts/memory_search.py` 与包装脚本 | 向量索引数据库（删掉重建） |
| 本地嵌入模型目录（或按需重下） | 水位线状态文件（新环境重新生成） |
| 提炼提示词 | 调度脚本（读日志的胶水层，与平台绑定） |

一句话：**记忆本体可搬，胶水层必须重写。**

## 2. 目标机步骤

1. 拷贝记忆库到目标机；路径不同则用环境变量覆盖，不要改文件里的硬编码。
2. 装 Python 依赖：`pip install sentence-transformers numpy`。
3. 准备嵌入模型：拷贝本地模型目录，或首次运行联网下载（受限网络可设 `HF_ENDPOINT=https://hf-mirror.com`）。
4. 建索引：`python scripts/memory_search.py index`。
5. 让新宿主每次会话读取规则：Claude Code 写 `CLAUDE.md`，Cursor 放 `.cursor/rules`，其它宿主贴进它自己的指令文件。
6. 重写胶水层：读新平台的会话日志 + 定时触发，调用同一份提炼提示词（见 `sync-pipeline.md`）。
7. 冒烟验证：`python scripts/memory_search.py search -q "记忆迁移"` 能返回结果。

## 3. 迁移后的 12 项验证

前 7 项验结构，后 5 项验**行为**（只验文件存在不算通过）：

1. 新宿主能读到规则入口与索引文件。
2. `L1-facts/` 能按日期定位到具体条目。
3. `L2-projects/` 里进行中的任务状态完整。
4. `L3-profile/user-profile.md` 每条都带来源与置信度。
5. 索引不含已删除文件。
6. 检索命中后能顺着来源指针找到原始证据。
7. 水位线文件可重建，且重建后不会重复处理。
8. 用一条 `confirmed` 偏好验证：能被召回并影响行为。
9. 用一条未确认推断验证：只进入 `candidates.md`，行为不变。
10. 用一条纠正验证：优先于旧画像，且冲突记录里留有旧值。
11. 用一条 `expired` 事实验证：不出现在注入内容里。
12. 跑一次"空增量"同步：应报告无新增且不产生任何写入。

## 4. 换宿主时必须重写的最小集合

只有三件事依赖平台，重写它们即可，其余照搬：

1. **读会话日志**：路径、格式、字段。
2. **定时触发**：调度器语法与补跑策略。
3. **会话开始的规则加载**：把规则入口挂到新宿主的指令文件或系统提示里。
